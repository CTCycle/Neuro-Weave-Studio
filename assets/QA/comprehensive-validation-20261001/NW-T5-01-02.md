  stopped at the 30-second PyTorch/Keras discovery deadline (31 passed, 1

  passed 32/32. The initial result is retained; no timeout/assertion was relaxed.

  be beneath `runtimes/cache`. The launcher cleaned up the preview service; the
  corrected canonical path launched successfully. This is a harness correction
  and an observed fail-closed configuration path, not an application defect.

  but waits for a download event timed out twice (20 and 10 seconds). No console

  proof remains incomplete; backend success is not substituted for that proof.
