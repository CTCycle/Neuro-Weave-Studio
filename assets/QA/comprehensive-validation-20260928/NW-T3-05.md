## Issue found and fixed during this slice

The first repository-wide backend run exposed a real compiler-gate defect:
worker probes report TensorFlow as `tensorflow_jit` and PyTorch as
`torch_compile`, while the controller checked only the UI-facing IDs
`tensorflow_function` and `pytorch_compile`. Consequently, an enabled native
TensorFlow XLA export was rejected even though the live probe was available.
The exact reproduction is preserved in the [compiler-alias reproduction note](logs/backend-nw-t3-05-compiler-alias-repro.md).
The controller now resolves the status through the existing alias-aware
`get_native_compilation_capabilities(...)` path. The exact failing TensorFlow
ONNX/XLA test passed after the fix, as did the existing unavailable-compiler
negative gate; the full backend suite then passed. This fix is within the
runtime/compiler boundary uncovered by the selected validation work.

The new browser harness also corrected an accessibility-name case mismatch and
asserts the required worker identity fields while allowing documented extra
worker metadata. These were harness issues, not product failures.
