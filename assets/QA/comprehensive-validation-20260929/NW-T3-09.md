## Defect found and fixed

The first live Dot Product attempt found a real ordering defect: Dot and
MatMul use one shared `tensor_list` input port, while `ordered_incoming_edges`
sorted same-port edges by random edge ID. A valid `[2,3] @ [3,4]` graph could
therefore be interpreted in reverse and rejected during connection validation.
The ordering helper now preserves graph connection order for edges sharing a
tensor-list port while retaining manifest order for named ports. The focused
regression `test_binary_merge_preserves_shared_tensor_list_connection_order`
and the final browser Dot/MatMul cases pass with this fix.

The first two browser iterations also exposed harness expectations: Stack’s
default axis inserts before batch, and dynamic Split accessibility labels use
the direction suffix `(output)` while persisted IDs remain `output_0` etc.
Those assertions were corrected before the final 15/15 run.
