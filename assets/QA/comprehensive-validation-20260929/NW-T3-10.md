## Issues fixed during validation

1. Connection validation rejected the first incoming edge for typed binary/
   elementwise operations because it treated an incomplete draft as a final
   arity failure. The service now defers that diagnostic until the declared
   arity is satisfied; the final graph still rejects insufficient operands.
2. Keras/PyTorch typed reductions returned `int32` for `math.argmin` despite
   the manifest's `int64` contract. Runtime emission now casts typed reduction
   results, and native JAX source enables x64 only for graphs that require an
   `int64` output.
3. `math.transpose.axes` was declared as a `shape`, whose editor rejects zero.
   Axis permutations legitimately contain zero, so the catalog parameter now
   uses the integer-axis contract and `[0, 2, 1]` persists through Builder.
