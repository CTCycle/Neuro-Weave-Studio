## Scope and implementation

This slice covers selection, Inspector editing and reset, undo/redo, dirty and
saved state, save/reopen persistence, and recovery from an invalid parameter
draft. It uses a four-node saved project in a run-specific SQLite database; it
does not claim full Model Builder catalog coverage or runtime execution.

The serial browser workflow exposed that graph history unconditionally cleared
node and edge selection. The graph editor now preserves a selected item when it
still exists in the restored graph and clears selection only when the item no
longer exists. A focused graph-store regression test covers node selection
through undo and redo. Playwright can now target an externally launched
`PLAYWRIGHT_BASE_URL`; the default dev-server behavior remains in place for
ordinary local and CI runs.

No public API changed. The separately requested Tier 0 recheck also extended
the project-discovery test wait to 30 seconds and corrected a Ruff `B009`
finding in a test helper.

## Results

The NW-T2-01 Playwright workflow passed **1 test in 5.1 seconds**, serially,
against the official Windows launcher preview and its isolated backend. It
verified:

- Selecting Hidden layer and Classifier updates the Inspector; the selected
  Hidden layer remains selected through undo and redo.
- Editing Units changes the Builder badge from **Saved** to **Drafting**.
  Undo and redo restore the prior and edited values. Reset parameters restores
  the catalog default and is itself undoable and redoable.
- Saving advances the project revision and persists the reset value through a
  reload.
- Entering `1.5` keeps the invalid value visible and editable, shows
  “Enter a valid units.”, and disables Save and Validate. The database graph and
  revision remain unchanged while that invalid draft is present.
- Replacing the draft with `24` enables saving. A second revision persists the
  repaired value through another reload.
- The test fixture is deleted in `finally` and verified absent. The browser
  reported zero page errors, console errors, failed requests, or HTTP errors.

Two persisted-project neighbor workflows passed **2/2 in 7.0 seconds**: the
valid Builder profile/validation/API-payload flow and the invalid
parameter-compatible draft gate. The focused graph-store and parameter-editor
tests passed **20/20**. The full frontend suite passed **104 tests in 20 files**;
frontend lint and the production build also passed. Fresh Tier 0 backend, Ruff,
and Pyright results are recorded in the [NW-T0-03 revalidation](NW-T0-03-revalidation-20260923.md).

The Codex in-app Browser independently inspected the production Builder UI.
It confirmed that the Inspector stays open during undo/redo, that invalid
`1.5` remains repairable while Save and Validate are disabled, and that `24`
saves as revision 3. See the [Browser observation](evidence/nw-t2-01-inapp-browser-observation.md)
and the saved [history/reset](evidence/nw-t2-01-reset-and-history.png),
[invalid draft](evidence/nw-t2-01-invalid-draft-repairable.png), and
