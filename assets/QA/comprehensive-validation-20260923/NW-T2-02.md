## Scope and implementation

This slice exercises Builder connector previews and readiness, valid and
rejected candidate edges, input cardinality, fan-out, inferred shapes, cycle
rejection, and repair of an invalid connection candidate. A six-node saved
graph runs in an isolated SQLite database through the official Windows
launcher. This is representative connection evidence; it does not certify the
full 149-node catalog or execution-profile matrix.

The checks exposed a mismatch between whole-graph validation latency and the
client's generic 10-second request timeout. The client now allows 60 seconds for
whole-graph validation while keeping per-connection checks at 10 seconds. An
API unit test covers both timeout choices. The graph-store and backend tests
also assert rejection when a non-multi-input port already has a connection.
The browser flow observes the computed `f-connector-connectable` state before
dragging and uses the server's candidate-validation response as the acceptance
signal; it does not use a fixed delay.

No public API changed.

## Results

The official launcher rebuilt the production frontend and reported it ready on
port 6425 with the backend healthy on port 9750. While the evidence was being
prepared, a later health check found that detached instance had stopped; an
interim browser attempt therefore had no available service. The official
launcher was run again and the complete browser rerun against healthy services
passed. The serial `workflows.spec.ts` suite passed **16/16** in 44.9 seconds,
including NW-T2-02 and surrounding Builder, validation, and project workflows.
The focused NW-T2-02 connection scenario passed **3/3 serial repeats**. The
connection scenario plus its edge-edit neighbor passed **4/4** in 12.1 seconds
with two workers against the isolated backend. No SQLite lock or
connector-readiness flake recurred in these bounded runs.

The workflow confirmed:

- A branch source can fan out to two Dense nodes and both branches can feed the
  merge's multi-input port.
- A shape-incompatible candidate is rejected with
  `incompatible_connection_shape` and leaves the graph unchanged. Editing the
  branch width repairs the candidate; the server accepts it and the edge is
  added.
- A proposed edge that closes a cycle is rejected with cycle feedback and does
  not increase the edge count.
- A single-input target at capacity is rejected in both frontend graph-store
  and backend connection-validation tests; supported merge fan-in remains
  accepted. The attention-mask incompatibility remains non-connectable.
- Whole-graph validation infers `[null, 16]` at the merge and reports a valid
  graph. The rendered screenshots show the shape labels and the cycle rejection
  state.

Focused backend validation passed **13 tests** (11 deselected from the three
selected modules). Focused frontend graph-store, API service, and compatibility
tests passed **39 tests in 3 files**. Pytest emitted a warning that its optional
node-id cache could not be written in the managed cache directory; all selected
tests passed and pytest exited successfully.

An earlier NW-T2-02 browser attempt exceeded Playwright's 30-second test
deadline while its `finally` block was deleting the fixture project. That
failure reproduction is retained in [the initial run log](logs/nw-t2-02-final.log).
The later complete suite, three serial repeats, and focused two-worker run all
passed; this cleanup timeout did not recur in those runs.

The in-app Browser independently rendered the six-node, five-edge saved graph.
After whole-graph validation it showed the branch, merge, and output dimensions
and Graph Health **No findings / Ready**. See the [Browser observation](evidence/nw-t2-02-inapp-browser-observation.md).

The connector-ready signal was already authoritative in the current Builder:
connectable candidates are synchronously reflected in the target connector's
state. The E2E test waits for that state and then checks the connection API
response. Repeated serial runs and the focused two-worker run passed, so
`ISSUE-002` is resolved for the covered workflow. This does not certify every
connector type or the full catalog.

`ISSUE-001` remains open. The current two-worker connection and edge-edit run
passed 4/4 without SQLite locking, and the default serial workflow passed. This
bounded check does not run the planned 1/2/4-worker matrix, so `NW-T5-02` and the
broader shared-database reliability claim remain untested.

The default Playwright `webServer` lifecycle ran `shell.spec.ts` with no
`PLAYWRIGHT_BASE_URL` override: **10/10 tests passed**, the command exited
naturally, and port 6426 had no listener afterward. `ISSUE-006` is resolved for
the current default Windows lifecycle. This run does not cover alternate shell
wrappers or every CI environment.
