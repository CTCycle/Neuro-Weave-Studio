## Validated behavior

- Custom metric and loss records survive a fresh catalog reload and carry the
  expected `regression`, `binary_classification`, and
  `multiclass_classification` task metadata.
- The persistent catalog advertises custom adapters only for Keras and native
  PyTorch. The focused API test confirmed the custom IDs appear in those two
  catalogs and do not appear in native TensorFlow or JAX catalogs; no fallback
  is implied.
- Built-in definitions remain locked. Unsafe expressions are rejected with
  HTTP 422 and an accessible rendered error. Saved-project references still
  block deletion through the existing conflict response.
- The UI now normalizes catalog options directly for view, edit, and delete,
  so custom loss actions do not depend on a stale metrics-definition signal.
