## NW-T2-05 — PASS

The official Windows launcher served the current application on backend port 9750 and preview port 6425 with an isolated database and tensor-inspection root. The workflow also verified the 64-bin histogram, hidden-state shape `[1, 4]`, identical values across the two entry points, explicit session deletion (`204`, followed by `404`), and cancellation of an active inspection without publishing a session. The API rejected a request for a noncurrent project revision with the typed `revision_conflict` response before worker submission. See the [rendered heatmap](evidence/nw-t2-05/nw-t2-05-builder-sequence-heatmap.png) and [browser log](logs/nw-t2-05-browser-e2e-20260924.log).

Two parameter cases also rechecked fail-closed native compiler rejection. All five passed; see the [backend test log](logs/nw-t2-05-backend-focused-20260924.log).

Visual validation caught two UI defects during this pass. The heatmap had fixed 64-column CSS even when the server returned a smaller exact slice, and native select controls could display their first option while the coordinator had selected another node or axis. The heatmap now derives its column count from `view_shape`, and the node and axis options reflect the selected values. The E2E gate asserts the selected node, axes, and rendered 3-by-4 cell geometry.

The server package manifest already declares the `tensorflow` optional backend extra, and the saved installation profile requested TensorFlow, PyTorch, and JAX. The project `app/server/.venv` was missing TensorFlow even though the setup record claimed completion; the [prior runtime discovery snapshot](evidence/nw-t4-02-runtime-discovery.json) recorded that dependency-missing state. The official `ManageBackends -Backends all` action reconciled the environment: the venv now contains TensorFlow 2.21.0, PyTorch 2.13.0+cu126, and JAX 0.11.0; the refreshed installation record has no failures and preserves the `tensorflow`, `torch-cu126`, and `jax` extras.

Reconciliation exposed Windows PowerShell 5.1 launcher incompatibilities that could prevent an accurate setup state from being recorded. The launcher now passes the Python backend-details probe as base64 so embedded quotes survive native argument marshaling, emits parsed backend arrays item by item, tolerates framework startup diagnostics on stderr while probing, preserves export tools during a base-environment repair, and computes repository-relative paths without the .NET API missing from Windows PowerShell 5.1. The official manager and launcher then completed successfully.

Current live runtime discovery reports TensorFlow 2.21.0 native CPU with `tensorflow_jit=true`, JAX 0.11.0 CPU with `jax_jit=true`, and PyTorch 2.13.0+cu126 with `torch_compile=false`. TensorFlow emitted `Compiled cluster using XLA!`. Neither smoke ran training or persisted model weights.
