# Runtime metadata contract

Last updated: 2026-10-21

`GET /api/metadata` is a cheap read. It returns the recorded package inventory, execution backends, per-API status, device and compiler information, and the compilation capability tree without importing optional ML frameworks or probing hardware. Each API status has a `state` (`unchecked`, `checking`, `verified`, `unavailable`, or `failed`), a `source` (`none`, `snapshot`, or `live`), and an optional `checked_at` timestamp. `unchecked` means that no live validation has happened; it must not be displayed as an absent package.

`POST /api/execution/discovery` accepts `{ "backend": "tensorflow|pytorch|jax", "api": "keras|native", "force_refresh": false }` and returns immediately with a `RuntimeDiscoveryResponse`. A request starts or joins one isolated probe for that backend/API pair. The controller limits concurrent probes to two, applies the database-backed runtime discovery timeout (60 seconds by default), and records `probe_timeout`, `dependency_missing`, import, and worker failures as actionable terminal states. `GET /api/execution/discovery?backend=...&api=...` reports progress and completion.

The snapshot defaults to `runtimes/cache/environment-discovery.json` and is display data until the requested pair has been fingerprint-validated in the current server session. Its path is a database-backed runtime setting restricted to the canonical cache root. The fingerprint includes interpreter, relevant packages, runtime configuration, hardware summary, and the backend-installation record. A matching snapshot can satisfy that pair without another framework import; a partial snapshot probes a missing pair, and a schema-version mismatch is discarded. Explicit refresh always bypasses the snapshot. Direct job submission requires a validated selected pair and returns `runtime_discovery_pending` while a check is running. Browsing, graph editing, saving, source generation, and export-capability reads do not require live discovery.
