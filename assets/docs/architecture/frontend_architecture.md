# Frontend Architecture

Last updated: 2026-08-31

The canonical Angular application lives in `app/client/src/app`. The standalone `AppShellComponent` owns primary navigation, route-level components are lazy-loaded from `app.routes.ts`, and typed API access is isolated in `core/api/api.service.ts` against the relative `/api` path. Framework-neutral graph contracts live in `domain/types.ts`; editor-only records live in `domain/editor.types.ts`.

The model catalog and model workspaces are reached through `/models`, `/models/:modelId`, `/models/:modelId/compilation`, `/models/:modelId/export`, and `/models/:modelId/inference`. New and existing architecture authoring is isolated under `/builder` and `/builder/:modelId`. `AppResourcesService` exposes independent signal-backed catalog, project, runtime, and capability readiness; each route explicitly loads only the resources it consumes, deduplicates concurrent reads, and provides a resource-level retry. The root resource service performs no network work in its constructor. `GraphEditorStore` owns the editable graph, history, selection, and serialization; and `BuilderTabsStore` retains a separate graph session and saved baseline per open model tab. This prevents browsing or switching models from mutating another editable draft. Foblex renders the graph through an adapter; it is never the persisted source of truth. Reusable standalone components implement catalog browsing, properties, validation, code preview, smoke inference, and model commands. Node rendering is registry-based through app-owned editor records and manifest implementation mappings.

`/api/metadata` supplies runtime `execution_backends`, per-backend API/compiler status, discovery state/source/time, and one capability-driven `configuration.compilation_capabilities` tree. `POST /api/execution/discovery` checks only the selected backend/API pair; compute routes observe it at 500 ms intervals with a bounded deadline and stop observing when navigated away. Unchecked metadata remains useful for the shell but cannot start a job until that pair is verified. Runtime discovery skips absent packages, records isolated worker results in a schema-versioned fingerprinted `environment-discovery.json` snapshot, and validates a matching snapshot on demand; explicit Environment controls remain the refresh path. A model's `execution_backend` and `keras_enabled` are persisted together; the Builder exposes them as a compact native-backend selector and explicit optional Keras API-layer toggle. Backend availability informs capability controls and runtime preferences, but it does not replace the persisted model profile. The dedicated `ModelExportPage` reads `GET /api/exports/{project_id}/capabilities`, groups the server-owned format matrix, exposes only format-specific options, and polls binary export jobs through verified completion.

The workspace preserves the drafting-board palette while reflowing at 1440/1200/1024px breakpoints. The Builder is dedicated to graph authoring, metadata, validation, and saving; compilation configuration and source generation belong to the Compilation page, while artifact downloads belong to the Export page. Its fixed-height editor uses a tab bar, compact authoring toolbar, node catalog, Foblex canvas adapter, inspector, and a bottom validation region with a pointer-resizable splitter. The description is edited through a small metadata popover and remains part of the canonical Builder tab/project metadata. The canvas has local minimap visibility and a focus mode that keeps the same Angular/Foblex editor instance mounted while temporarily hiding nonessential chrome. At 1024px and below the Catalog and Inspector become explicit drawers; the canvas and validation region remain within the viewport without document scrolling. Catalog, workspace, workflow, environment, and metrics surfaces share the available content width and a stable scrollbar gutter.
