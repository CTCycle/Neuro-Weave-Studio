# Serialization and Versioning

Last updated: 2026-09-01

The canonical graph is version 4 and the portable NeuroWeave project bundle is version 5. A graph stores one `model_configuration` value with explicit `keras` and `native` branches; native TensorFlow, PyTorch, and JAX compiler settings are independent and disabled by default. Nodes persist their canvas lock state, and `output_bindings` stores explicit node-port selections; an empty selection means that unconsumed value-producing terminal ports are inferred as outputs. Output adapter nodes remain supported as optional semantic/task boundaries, but they are not required to terminate a workflow. A project bundle also stores `execution_backend`, `keras_enabled`, the graph, and revision-independent export settings. Node definitions have independent stable IDs and integer versions. Readers accept only the current graph and bundle versions and reject unsupported future versions; the forward Alembic migrations `20260827_canonical_model_configuration` and `20260901_model_builder_graph_boundaries` are the only database upgrade path. There are no runtime dual readers, aliases, or compatibility shims. Project revisions are application history, not schema versions.

Generated source snapshots retain the model execution profile used for the current revision. A `.keras` binary is an initialized artifact, not a portable project bundle. A `.keras` architecture import reads only allowlisted configuration metadata and creates a new canonical graph; weights, optimizer state, and custom Python objects are not serialized into the NeuroWeave project.
