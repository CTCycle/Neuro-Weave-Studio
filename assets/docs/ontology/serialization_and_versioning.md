# Serialization and Versioning

Last updated: 2026-09-02

The canonical graph is version 5 and the portable NeuroWeave project bundle is version 6. A graph stores one `model_configuration` value with explicit `keras` and `native` branches; native TensorFlow, PyTorch, and JAX compiler settings are independent and disabled by default. Nodes persist their canvas lock state, and `output_bindings` stores explicit node-port selections; an empty selection means that unconsumed value-producing terminal ports are inferred as outputs. Output adapter nodes remain supported as optional semantic/task boundaries, but they are not required to terminate a workflow.

Graph schema 5 stores model input shapes as feature dimensions only. Runtime batch is not part of persisted architecture state. For example, a tabular model with 20 features stores `[20]`; validation, source generation, and workers consume the equivalent runtime shape `[None, 20]`. `input.parameter` remains an explicitly unbatched parameter shape and is not transformed by the batch-shape migration. Empty quantization placeholders are omitted rather than serialized as active configuration.

A project bundle stores `execution_backend`, `keras_enabled`, the graph, and revision-independent export settings. Node definitions have independent stable IDs and integer versions. Canonical writes always emit graph version 5 and bundle version 6. The immediately preceding graph version 4 and project bundle version 5 are accepted only at the import/model-validation boundary and are normalized once to the canonical representation. Unsupported older or future versions are rejected. Persisted databases are upgraded by Alembic, including `20260827_canonical_model_configuration`, `20260901_model_builder_graph_boundaries`, and `20260902_runtime_batch_shapes`; runtime services do not maintain parallel persisted representations. Project revisions are application history, not schema versions.

Generated source snapshots retain the model execution profile used for the current revision. A `.keras` binary is an initialized artifact, not a portable project bundle. A `.keras` architecture import reads only allowlisted configuration metadata and creates a new canonical graph. Keras `batch_shape` and `batch_input_shape` values have their leading batch element removed during import, while `input_shape` is already interpreted as feature-only. Weights, optimizer state, and custom Python objects are not serialized into the NeuroWeave project.
