# Editor Interactions

Last updated: 2026-09-02

Users drag catalog items onto the Angular canvas, connect typed ports, select nodes or edges, and edit the complete manifest-driven property surface. Foblex supplies rendering and pointer gestures through the adapter; the neutral graph store remains authoritative. The canvas supports pan, zoom, fit view, a minimap, snap-to-grid placement, automatic layered layout, and a concise empty-canvas context menu. Connections use stable straight paths, including the live source-to-cursor preview, so nearby and distant nodes share one predictable geometry. While connecting, semantic target ports are highlighted and incompatible or unavailable targets are dimmed. A source output can fan out to multiple downstream nodes; input multiplicity remains defined by the target port. Attempts that would create a cycle, violate port kinds or enabled conditions, or overfill a single-input port are rejected before the edge is created and report immediate feedback without adding undo history.

The Node catalog keeps search and category grouping but uses compact rows to preserve vertical density. Advanced filters are progressive rather than permanently occupying panel space. They are derived from manifest metadata and can restrict by category, current or explicit backend compatibility, port kind, operation family, and operation shape behavior. Active filters are visible as removable controls and can be cleared together. Unsupported nodes remain editable but are marked as limited for the selected execution profile.

Copy and paste duplicate the selected node without its connections. A node context menu also provides exact duplication, duplication with active framework defaults, reset parameters, disconnect-all, lock/unlock, explicit output assignment, and deletion. Locked nodes remain selectable, configurable, connectable, duplicable, and deletable but cannot be moved. Undo and redo cover node creation, connection creation, deletion, property changes, output/lock state changes, model configuration changes, node movement checkpoints, paste operations, and automatic layout. Keyboard commands use Ctrl or Command with Z, Shift+Z, Y, C, V, and L. Reduced-motion preferences disable nonessential animation.

The Builder keeps open models in a tab bar. Each tab owns a graph snapshot, metadata snapshot, saved baseline, and dirty state; switching tabs restores the selected session without losing another model's draft. Closing a dirty tab requires confirmation. New tabs create isolated drafts and never duplicate a persisted project ID.

The toolbar edits the model name, opens a compact canonical description popover, selects the persisted native execution backend through an accessible dark themed picker, explicitly toggles the optional Keras API layer, and exposes Validate, Save model, undo, redo, and workspace actions. Compilation configuration, validation, and source generation continue in the dedicated Compilation workspace. The backend selector remains the native execution choice; Keras is an optional abstraction over it, not a competing backend.

The fixed editor workspace is a three-column layout: Node catalog, center workspace, and Inspector. The center contains the model tab bar, canvas, and bottom Validation panel. The minimap can be hidden locally so it releases its canvas area. Focus mode keeps the same Angular/Foblex graph instance mounted, hides nonessential surrounding panels, and restores the normal layout with Escape or Exit full canvas without fitting or resetting the viewport. The validation splitter changes the panel height continuously while preserving a minimum canvas height; diagnostics scroll inside the panel instead of growing the document.

Right-clicking an empty canvas opens Fit workflow to view, Auto layout, and Reset canvas. Reset always opens a confirmation dialog explaining that all nodes and connections will be removed. Right-clicking a node exposes the node actions without adding a separate output-node requirement; output indicators distinguish inferred terminal outputs from explicit selections. The Inspector starts with a compact node identity/status header, renders non-nullable boolean parameters as checkboxes, retains dropdowns for finite enum choices and nullable booleans, and presents port specifications as dense input/output rows with type, shape, cardinality, and connection status.

Input shape editing follows graph schema 5. The editable value contains feature dimensions only and never stores a runtime batch axis. Input shape controls expose a `Show batch dimension` checkbox, disabled by default, which renders a read-only runtime preview such as `[batch, 20]`; the preview is local UI state and is never serialized. Optional quantization configuration is considered disabled when it is absent, blank, an empty object, or an object with an empty `class_name` and empty `config`. Those placeholder values are removed from the graph instead of being persisted as active quantization settings.
