# Model Catalog, Builder, and Workspaces

Last updated: 2026-09-10

The model catalog is the application home at `/models`. It is a library of persisted models backed by the `Project` aggregate and `/api/projects` endpoints. Catalog cards are summary-only: they show name, description, updated time, revision, restrained backend/API metadata, graph-derived input/output and node/edge counts, flat validation/compilation indicators, and whether source exists for the current revision. Input counts use manifest semantic roles; output counts use the same explicit-or-inferred effective-output rules as validation. Search and compiled/validation segmented filters operate on that in-memory summary list. JSON project import and `.keras` architecture import are explicit catalog actions.

## Responsibilities

- `/builder` creates a model and `/builder/:modelId` edits its architecture. The Builder owns graph authoring, node configuration, validation, undo/redo, naming, description, the persisted execution profile, and explicit save. It exposes Save, Validate, undo, and redo. Compilation settings, source generation, inference, export, duplicate, import/export, and model browsing belong to dedicated workspace flows.
- `/models/:modelId` is a read-only overview with a Foblex-backed architecture preview, canonical graph-derived I/O counts, configuration/readiness summaries, management actions, and links to dedicated workflows.
- `/models/:modelId/compilation` owns capability-driven Keras/native configuration, resolves effective graph outputs, validates and revision-safely saves the selected profile, generates a source snapshot, and exposes generated source viewing/copying. Native TensorFlow, PyTorch, and JAX settings use the selected backend's own catalog; PyTorch loss/metric settings are not edited or displayed for another backend. A preflight with blocking findings leaves the saved revision/configuration unchanged. It does not download source or binary artifacts.
- `/models/:modelId/export` consumes the server-owned export capability matrix and owns project/source downloads plus verified binary export jobs with runtime/API/device/policy diagnostics and a gated artifact download.
- `/models/:modelId/inference` remains directly routable for isolated saved-graph smoke jobs, but it is no longer a primary workspace tab. Navigation foregrounds Overview, Compilation, and Export. The inference route still polls lifecycle progress, exposes Stop, and retains the explicit no-training/no-weight-updates message.
- `/datasets` is a persisted metadata workspace. Its typed wizard supports tabular, image, text, time-series, array/tensor, and composed organizations, with source inspection, explicit input/output/metadata/unused roles, optional all/first-N/range subsets, authoritative validation, and create/update registration. Auto Detect is disabled. The filesystem explorer selects real local paths through the backend; dataset bytes are not copied or persisted. The catalog reports live source availability, and the nested workspace provides Overview and Structure plus future-only Processing and Split routes.
- `/training` is a primary bootstrap workspace. A training draft pairs a saved model with a persisted dataset summary and basic epochs/batch-size configuration, then appears as a card similar to the model catalog. Training drafts are not persisted and cannot start a worker, fit loop, weight update, or checkpoint yet.
- `/metrics` keeps the server-owned built-in loss and metric catalog read-only, while allowing session-only custom definitions through a wizard that accepts direct LaTeX or a guided equation builder. Custom definitions are previewed with KaTeX and are not yet selectable in Compilation or Training.

The selected model workspace header shows input/output counts alongside node/connection totals so model boundaries are visible without opening the Builder. Workspace management actions are deliberately explicit: the Export workflow downloads the persisted JSON bundle, duplicate opens the new model workspace, and deletion requires an in-app confirmation dialog.

Catalog/workspace data is separate from the editable Angular graph store. The store is initialized only for Builder routes, while workspace previews use the same node visuals and drafting-board styling in a read-only Foblex canvas with a scoped store. `BuilderTabsStore` holds independent sessions and saved baselines for each open tab; navigation is guarded when any tab is dirty, and users can stay or discard changes before leaving. Dataset registrations are owned by the backend and `AppResourcesService`/`DatasetWorkspaceState`; `ExperimentDraftsService` retains only session training and custom-equation bootstrap state.

The Environment page owns session-scoped API, backend, device, and memory-policy selection plus active-worker diagnostics. When a selection is used by a live job it offers Stop and switch or Keep running/use for later jobs. The application shell keeps Models, Model Builder, Datasets, Training, Environment, and Metrics in primary navigation; the model workspace navigation intentionally has no Inference tab, while inference remains an explicit dedicated workflow action. Below 1024px, Builder retains the compact Catalog/Inspector drawer behavior, progressive catalog filters, and graph-derived counts rather than introducing a second visual language.
