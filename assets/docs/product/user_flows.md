# User Flows

Last updated: 2026-08-27

The application opens on the model catalog (`/models`). Users browse or filter saved models, select one for a read-only overview, and choose a dedicated Compilation or Inference workspace. The Model Builder (`/builder`) is reserved for creating a model; `/builder/:modelId` edits an existing architecture. In Builder, users set the execution backend and Keras/native mode, drag nodes from the catalog, connect typed ports, configure every exposed node property, validate, and explicitly save. Multiple open models use isolated tabs. Save and Save & compile persist the draft; the latter also creates source for the current revision. Unsaved Builder changes warn before internal navigation or browser unload.

The model overview supports architecture inspection, duplicate, the unified Model Export center, `.keras` architecture import, and confirmed delete. Training is represented as a disabled planned capability rather than a route or backend contract. Reopening restores the graph and revision. Compilation source snapshots are revision- and profile-specific. The export center consumes the live capability matrix, groups project/source/native/interchange/checkpoint methods, explains disabled formats, and shows only options supported by the selected format. Project JSON and source download immediately; binary artifacts remain in the job workflow until verified success.

For binary export and inference, the Environment page discovers live API/backend/device/policy capability from `/api/metadata`. It shows supported memory policies per device and keeps selection session-scoped. Each export is a job: phase, device, revision, verification, cancellation, and failure diagnostics remain visible; the artifact download is enabled only after verified success. If an active job uses the current selection, users choose Stop and switch or Keep running/use the new selection later. Keras remains the model API layer; native workers use raw framework APIs and only advertise their verified profile subset.
